# Document vivant d'une fonctionnalité Hall

Le même document Maket accompagne une fonctionnalité du cadrage à la livraison.
Il présente les informations de leurs autorités; il ne devient pas un second
catalogue d'exigences ni un second Plan TRUST.

Lire la [carte opérationnelle](trust-operations.md) pour connaître la phase et
les Plans, puis le [workflow de livraison](trust-workflow.md).

## Informations présentées

| Information | Autorité |
| --- | --- |
| Exigence et critères | [Catalogue Hall](../requirements/catalog.json) |
| Décision produit | the user |
| Mission, dépendances et Result | Plan TRUST |
| Constat de revue | Rapport sourcé de l'agent |
| Résultat d'exécution | Sortie de l'Operation |
| Verdict du Check | TRUST |
| Présentation | Maket |

Le document montre le périmètre, les décisions, les inconnues, les missions, les
constats, les preuves et le reste à faire. Une maquette reste identifiée comme
proposition; un résultat d'exécution reste rattaché au code et à la tentative
observés.

## Mise à jour

1. Lire le Plan, les verdicts, les rapports et les exigences concernés.
2. Conserver leur provenance et distinguer absence, échec, réussite et résultat
   historique.
3. Écrire la nouvelle révision Maket avec contrôle de concurrence, puis relire
   le contenu enregistré.
4. Préserver les commentaires et décisions humains.
5. Afficher un échec de synchronisation au lieu d'annoncer une mise à jour.

Une Operation TRUST porte la lecture et la projection nécessaires. Elle peut
appeler une commande Hall durable de la
[carte des contrôles](trust-verification-map.md), mais Hall ne conserve pas de
script propre à une mission TRUST.

## Fin

Le document est à jour lorsque le périmètre approuvé, les exigences livrées, les
revues, les contrôles exécutés, les échecs et les décisions ouvertes concordent
avec leurs autorités. Un Plan `COMPLETE` qualifie sa Procedure; il ne prouve pas
à lui seul que toute la fonctionnalité Hall est livrée.
